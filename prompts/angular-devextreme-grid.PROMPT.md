# Build "Catalog" — an Angular 22 + DevExtreme DataGrid app on a .NET 10 API

> ## READ FIRST (1) — DevExtreme is commercial software
> `devextreme` / `devextreme-angular` require a **paid, per-developer DevExpress licence**.
> Free 30-day trial: https://js.devexpress.com/Download/
> Without a key the components run fully but render an "unlicensed version" banner and log a warning.
> **You do not need a key to finish this task.** The `prebuild`/`prestart`/`pretest` scripts run
> `devextreme-license --out src/.devextreme/license-key.ts --force` (binary ships inside the
> `devextreme` package); with no key it writes `export const licenseKey = 'TRIAL';` and exits 0.
> If you own a licence put it in `%APPDATA%\DevExpress\DevExpress_License.txt` (or set
> `$env:DevExpress_License`) and the same command picks it up. The generated file is gitignored.
> Everything else is free: `DevExtreme.AspNet.Data` MIT, `devextreme-exceljs-fork` MIT, `file-saver` MIT.

> ## READ FIRST (2) — Node version is a hard gate
> Angular CLI 22 declares `engines.node = "^22.22.3 || ^24.15.0 || >=26.0.0"` and **refuses to start**
> on anything else (including Node 20.x and Node 22.22.2). Run `node --version` before anything.
> If it does not satisfy that range, install Node 24 LTS first — nothing below will work.

> ## READ FIRST (3) — unsupported-but-verified combination
> devextreme-angular 26.1.3 is compiled against Angular 20.3 (peer `@angular/core >=20.0.0`), so it
> installs on Angular 22 with no peer conflict. DevExpress publishes **no** Angular 22 support
> statement. Zoneless has been checked against the shipped bundle and works, but keep **all** app
> state in signals. Escape hatch if you hit stale rendering: regenerate with `--zoneless=false`.

## Requirements

### A. Domain and deterministic seed

1. `Product`: `Id` (int, PK), `Sku` (string, required, unique, <= 16), `Name` (string, required, <= 120),
   `Category` (string, one of `Tools`, `Hardware`, `Fasteners`, `Electrical`, `Safety`),
   `UnitPrice` (decimal, > 0), `UnitsInStock` (int, >= 0), `Discontinued` (bool),
   `LastRestockedUtc` (DateTime), `SupplierNotes` (string?, <= 500).
2. **One RNG, implemented identically in C# and TypeScript** (Park–Miller; exact in `long` and in IEEE
   doubles, so both sides produce byte-identical rows):
   ```
   state = 20260727
   next() { state = (state * 16807) % 2147483647; return (state - 1) / 2147483646.0; }
   ```
   Word lists, shared verbatim:
   `CATEGORIES = ['Tools','Hardware','Fasteners','Electrical','Safety']`
   `ADJECTIVES = ['Heavy','Compact','Precision','Industrial','Coated','Stainless','Rapid','Modular']`
   `NOUNS      = ['Wrench','Bracket','Anchor','Relay','Harness','Clamp','Bushing','Gasket']`
   For `i = 1..250`, draw eight values **in this order**:
   `Category = CATEGORIES[floor(r1*5)]`; `adj = ADJECTIVES[floor(r2*8)]`; `noun = NOUNS[floor(r3*8)]`;
   `Name = "{adj} {noun} {i}"`; `Sku = "SKU-" + i padded to 4 digits`;
   `UnitPrice = floor((1.50 + r4*998.49) * 100) / 100`; `UnitsInStock = floor(r5*500)`;
   `Discontinued = r6 < 0.08`;
   `LastRestockedUtc = 2026-07-27T00:00:00Z minus floor(r7*400) days`;
   `SupplierNotes = r8 < 0.4 ? "Lead time " + (1 + floor(r8*30)) + " days" : null`.
   Exactly **250** rows, unique `Id` (1..250) and unique `Sku`.
3. `CatalogDbContext` uses SQLite, connection string `ConnectionStrings:Default`
   (default `Data Source=catalog.db`). Expose `public DbSet<Product> Products => Set<Product>();`
   (avoids CS8618 under `TreatWarningsAsErrors`). On startup: `Database.EnsureCreated()`, and if
   `Products` is empty insert the seed. No EF migrations, no `dotnet-ef`.

### B. REST contract (DevExtreme.AspNet.Data protocol)

4. `GET /api/products` takes DevExtreme load options from the query string (`skip`, `take`, `sort`,
   `filter`, `requireTotalCount`, `totalSummary`, `group`, `groupSummary`, `requireGroupCount`) and
   returns `{ "data": [...], "totalCount": n }`. Bind with this exact pattern — no MVC controllers,
   no custom JSON parsing:

```csharp
using DevExtreme.AspNet.Data;
using DevExtreme.AspNet.Data.Helpers;

public sealed class DataSourceLoadOptions : DataSourceLoadOptionsBase
{
    public static ValueTask<DataSourceLoadOptions?> BindAsync(HttpContext ctx)
    {
        var options = new DataSourceLoadOptions();
        DataSourceLoadOptionsParser.Parse(options, key => ctx.Request.Query[key].FirstOrDefault()!);
        options.PrimaryKey = [nameof(Product.Id)];
        if (options.Take <= 0 || options.Take > 500) options.Take = 500;   // server cap, NOT a page size
        return ValueTask.FromResult<DataSourceLoadOptions?>(options);
    }
}
```
   The handler is `DataSourceLoader.LoadAsync(db.Products.AsNoTracking(), options, ct)`.
   Never materialise before loading. **The cap must be 500, not the page size**: the grid's Excel export
   issues a load with no `take`, and clamping that to 20 would silently truncate the workbook.
5. `GET /api/products/{id}` -> 200 `ProductDto` or 404 `ProblemDetails`.
6. `POST /api/products` (`ProductWriteDto`) -> 201 + `Location`; `PUT /api/products/{id}` -> 200;
   `DELETE /api/products/{id}` -> 204. Unknown id -> 404.
7. Write validation: required `Sku`/`Name`, `UnitPrice > 0`, `UnitsInStock >= 0`, `Category` in the
   allowed set, `Sku` unique. Failures return **400 `ValidationProblemDetails`** whose `errors` keys are
   camelCase field names (`sku`, `name`, `unitPrice`, `unitsInStock`, `category`).
8. `AddOpenApi()` + `MapOpenApi()`. `Properties/launchSettings.json`: a single `http` profile with
   `"applicationUrl": "http://localhost:5225"` and `"launchBrowser": false`.
9. `Program.cs` ends with `public partial class Program;` so `WebApplicationFactory<Program>` can host it.

### C. Angular data layer

10. `src/app/products/product.model.ts` — `Product`, `ProductWriteDto`, `CATEGORIES` (const tuple),
    `LoadResult<T> = { data: T[]; totalCount: number }`. No devextreme imports.
11. `src/app/products/product-query.ts` — **pure**, only `import type { LoadOptions } from 'devextreme/common/data'`. Exports:
    - `toQueryParams(options: LoadOptions<Product>): Record<string, string>` — serialises `skip`, `take`,
      `sort`, `filter` (JSON), `requireTotalCount`; omits empty keys.
    - `applyLoadOptions(rows: Product[], options: LoadOptions<Product>): LoadResult<Product>` — the
      offline engine. Operators `=`, `<>`, `<`, `<=`, `>`, `>=`, `contains`, `notcontains`,
      `startswith`, `endswith`, `between`, the `!` negation form, `and`/`or` nesting; multi-key sort;
      `skip`/`take`. Case-insensitive string comparison. `totalCount` reflects the filter, not the page.
12. `src/app/products/product-api.ts` — `@Injectable({ providedIn: 'root' })`, `inject(HttpClient)`,
    base `/api/products`. Methods `load`, `byId`, `create`, `update`, `remove`, all typed, all returning
    `Promise` via `firstValueFrom`. No devextreme imports.
13. `src/app/products/product-seed.ts` — `PRODUCT_SEED: Product[]`, produced by the **exact** algorithm
    in requirement 2 (same LCG, same draw order).
14. `src/app/products/product-store.ts` — `createProductStore(api, onModeChange)` returning
    `CustomStore<Product, number>` (`import { CustomStore } from 'devextreme/common/data'`) with
    `key: 'Id'`, `loadMode: 'processed'`. `load` calls `api.load(toQueryParams(opts))`.
    **Offline rule, exactly:** an `HttpErrorResponse` with `status === 0 || status >= 500` flips to
    offline mode, reports it through `onModeChange(true)`, and answers from
    `applyLoadOptions(PRODUCT_SEED, opts)`; a 4xx is re-thrown as an API error. (The Angular dev-server
    proxy answers **500/504** when the API is down — status 0 alone would never fire.)
    `insert`/`update`/`remove` map a 400 `ValidationProblemDetails` into an `Error` whose message is the
    joined field errors, so the grid's error row shows them.

import { saveAs } from 'file-saver';
import { exportDataGrid } from 'devextreme/common/export/excel';
import { DxDataGridTypes } from 'devextreme-angular/ui/data-grid';

async onExporting(e: DxDataGridTypes.ExportingEvent): Promise<void> {
  const workbook = new Workbook();
  const worksheet = workbook.addWorksheet('Products');
  await exportDataGrid({ component: e.component, worksheet, autoFilterEnabled: true });

}

## Acceptance criteria

Every command is absolute — do **not** chain with `&&` (invalid in Windows PowerShell 5.1).

1. `Set-Location <repo>\web ; npm run lint` -> exit 0 (the script is `ng lint --max-warnings 0`, so any
   warning is a failure).
2. `Set-Location <repo>\web ; npm run build` -> exit 0; no budget error; no CommonJS warning for
   `devextreme-exceljs-fork` or `file-saver`.
3. `Set-Location <repo>\web ; npm test -- --no-watch` -> exit 0; **>= 20 tests pass, 0 fail**; coverage
   thresholds met (statements 90 / branches 80 / functions 90 / lines 90 over
   `product-query.ts` + `product-api.ts`).
4. `Set-Location <repo>\api ; dotnet build -warnaserror` -> exit 0.
   `Set-Location <repo>\api ; dotnet test` -> exit 0, **>= 6 tests pass**.
5. With the API running:
   `(Invoke-RestMethod "http://localhost:5225/api/products?take=20&requireTotalCount=true").data.Count`
   prints `20`, and `.totalCount` prints `250`.
6. Paging is server-side:
   `(Invoke-RestMethod "http://localhost:5225/api/products?skip=240&take=20").data.Count` prints `10`.
   Export path is not truncated:
   `(Invoke-RestMethod "http://localhost:5225/api/products").data.Count` prints `250` (cap is 500).
7. Both running, `http://localhost:4200`: the grid shows **20 rows, "Page 1 of 13"**. Go to the last
   page — DevTools Network shows exactly one request whose query string contains `skip=240` and
   `take=20`, and whose response body has **10** rows. No grid paging request returns 250 rows.
8. Stop the API and reload: the grid still shows **250 rows over 13 pages**, the amber
   *"API unreachable — showing 250 seeded demo rows"* banner is visible, and the add/edit/delete buttons
   are disabled. Filtering and sorting still work client-side.
9. Restart the API. Edit a row, clear `Name` -> the popup blocks save with a required-field error.
   Set `UnitPrice` to `0` -> save is rejected and the message names `unitPrice`. Set a valid value ->
   the row persists across a page refresh.
10. Click Export -> `products.xlsx` downloads, opens in Excel, has an auto-filter header row, and its
    row count equals the currently filtered count (filter to a subset first and confirm it is **not** 250
    and **not** 20).
11. Click Details -> `/products/{id}` renders that product. `/products/999999` renders a "not found"
    state, not a crash. An unknown route renders NotFound.
12. `Set-Location <repo> ; git status --porcelain` lists no `web/src/.devextreme/license-key.ts` and no
    `*.db` files.

## Out of scope

Do not build: authentication/authorisation/Identity; SSR/SSG; Docker or CI; a theme switcher (light
only); master-detail rows inside the grid (the detail is a route); grouping UI beyond the built-in group
panel; PDF export; i18n; SignalR or live updates; EF migrations (`EnsureCreated` is deliberate); custom
CSS beyond ~40 lines of layout; a component library or design system; charts; virtual/infinite scrolling;
unit tests for the grid component itself. Do not upgrade past the pinned versions.
Do not run `ng add devextreme-angular`. Do not install `typescript@latest`.

## Troubleshooting (only if hit)

- **`ng new` prints "The Angular CLI requires a minimum Node.js version of v22.22.3…"** — your Node is
  too old. Install Node 24 LTS. Nothing else will work first.
- **`ng build` fails with `TS7016: Could not find a declaration file for module 'devextreme/common/config'`**
  — you used the untyped path. It must be `devextreme/core/config`.
- **`ng build` fails on a TypeScript version mismatch** — you have `typescript@7`. Run
  `npm install -D typescript@~6.0.2`.
- **`dotnet build` prints `MSB1003: Specify a project or solution file`** — you are in `api/` without
  `Catalog.slnx`. Re-run the `dotnet new sln` + `dotnet sln add` step.
- **`dotnet new xunit3` says the template was not found** — run
  `dotnet new install xunit.v3.templates::3.2.2` first; it is not in the SDK.
- **Grid renders but no data and no error** — the proxy is not loaded. `npm start` must include
  `--proxy-config proxy.conf.json`.
- **Grid shows the API-error banner instead of the amber offline banner when the API is down** — your
  offline check tests only `status === 0`. The dev-server proxy answers 500/504; the rule is
  `status === 0 || status >= 500`.
- **A dxTemplate renders stale under zoneless** — verified not to happen with devextreme-angular 26.1.3
  (`DxTemplateDirective.render()` calls `detectChanges()` itself). If it somehow does, regenerate the
  workspace with `--zoneless=false`; do not sprinkle `ChangeDetectorRef` through app code.
